# DSD브릿지: 전기 .dsd + 당기 정산표 → 당기 .dsd

DART 제출용 감사보고서 `.dsd`(ZIP 안 contents.xml·meta.xml)를 다음 기수로 넘긴다. 프로그램 DSD브릿지(`dsd_bridge.py`)가 펼치기·되돌리기·검증을 맡고, **판단이 필요한 편집(이월, 정산표 숫자를 계정에 맞춰 채우기)은 Claude 가 한다.** 사용자는 회계사다. 답은 한국어로, 회계·감사 용어는 풀어 쓰지 않는다. 산출물(dsd·엑셀·메모)에 긴 줄표 '—' 를 쓰지 않는다.

```
검토 끝난 당기 정산표 + 전기 감사보고서 .dsd → [DSD브릿지] → 당기 감사보고서 .dsd → (사전재무제표 .dsd) → 사용자: DART 편집기 검사·등록
```
보고서 숫자는 **검토 완료 정산표** 기준이다. 전기 열도 전기 공시값이 아니라 검토 완료 정산표의 전기 값(재분류·정정 반영)이다. 정산표가 아직 검토 전이면(당기 열이 옛 원천을 보거나 검증셀이 FALSE) 사용자에게 먼저 알린다.

## 0. 설치와 위치 (처음 쓰는 PC)

- **프로그램 폴더** = 이 플러그인의 루트 = 이 스킬 폴더(이 파일이 있는 곳)의 **두 단계 위**. 그 안에 `dsd_bridge.py`·`dsd-bridge.cmd`·`setup.ps1`·`requirements.txt` 가 있다. 아래에서 `<루트>` 로 쓴다.
- **전용 파이썬**(venv): Windows `%LOCALAPPDATA%\dsd-bridge\.venv\Scripts\python.exe`, 맥 `~/.venvs/dsd-bridge/bin/python`. 플러그인 폴더 밖에 두므로 플러그인을 업데이트해도 다시 만들 필요가 없다.
  - 없으면 만든다: Windows `powershell -ExecutionPolicy Bypass -File "<루트>\setup.ps1"`, 맥 `bash "<루트>/setup.sh"`.
  - 실행 정책으로 막히면 손으로: `py -3.13 -m venv "%LOCALAPPDATA%\dsd-bridge\.venv"` → 그 파이썬으로 `-m pip install -r "<루트>\requirements.txt"`.
  - 파이썬 3.13 이상이 없으면 사용자에게 설치를 안내한다(https://www.python.org/downloads/ 또는 `winget install Python.Python.3.13`).
  - 확인: `<파이썬> "<루트>/dsd_bridge.py" --version` 이 `dsd-bridge 0.x.y` 를 출력.
- 아래 명령의 `dsd-bridge` = `<파이썬> "<루트>/dsd_bridge.py"`. 출력 한글이 깨지면 `PYTHONIOENCODING=utf-8`(또는 `PYTHONUTF8=1`). `python -I` 는 쓰지 않는다.
- **DART 편집기**: Windows `C:\DART`. XSD(파일 규칙)는 `C:\DART\Resource\Dtd\Dart4.xsd` 를 자동으로 찾는다. 다른 곳이면 환경변수 `DSD_BRIDGE_DART_XSD_DIR`. 표준계정코드 표는 `C:\DART\Resource\Code\A\`.
- 이 스킬의 `scripts/`: `dsd_period.py`(기간 표기 일괄 갱신), `dsd_insert_rows.py`(병합 표 안 행 삽입, Windows 엑셀 필요), `dsd_xml.py`(되돌린 뒤 XML 후처리·점검·XSD), `dsd_prefs.py`(사전재무제표 만들기). 같은 `<파이썬>` 으로 실행한다.
- 경로에 작은따옴표(`'26.09월`) 같은 특수문자가 있으면 스크립트에 경로를 인자로 넘긴다.
- **고객 파일은 고객 폴더에서만** 다루고 플러그인 폴더에 넣지 않는다. 작업 중간 파일은 임시 폴더(`$CLAUDE_JOB_DIR/tmp` 가 있으면 그곳), 결과물은 고객 기수 폴더에 **새 이름으로**(원본 덮어쓰기 금지).

## 1. 고객 메모 (사용자마다 따로)

반복 고객은 고객 메모를 쌓아 두면 다음 기수가 빨라진다. 메모는 **이 PC 사용자 것**이고 플러그인 폴더에 두지 않는다(업데이트 때 지워짐).

- 위치: `~/.dsd-bridge/config.json` 의 `clients_dir`(있으면), 없으면 `~/.dsd-bridge/clients/`(Windows `%USERPROFILE%\.dsd-bridge\clients\`). 파일 이름은 `<고객 이름>.md`.
- **시작할 때**: 그 고객 메모가 있으면 먼저 읽고 따른다(정산표 시트 대응, 보고서 규칙, 지난번 고친 점). 이름이 조금 달라도(약칭 등) 비슷한 파일을 찾아본다.
- **끝날 때**: 이번에 알게 된 것(정산표 시트·열 대응, settlement-map, 이월 때 고친 전기 오류, 사용자 결정, 작업 이력 한 줄)을 메모에 남길지 한 줄로 묻고, 사용자가 원하면 `templates/client-memo.md` 틀로 만들거나 고친다. config 에 `"memo": "auto"` 가 있으면 묻지 않고 바로 쓴다.
- 메모에는 금액 상세·개인정보를 적지 않고, 판단 규칙과 위치만 적는다.

## 2. 시작 전 확인

전기 .dsd(날인본과 같은지), 검토 완료 당기 정산표, 기간 정보(제N기, 당기·전기 시작/종료일), 고객 메모의 보고서 규칙. 정산표에 없는 감사 정보(감사보고서일, 외부감사 실시내용 인원·시간·일정, 지배기구 커뮤니케이션 일자)는 `○` 로 두고 마지막에 요청한다. 임의감사처럼 외부감사 실시내용이 필요 없는 고객도 있다(고객 메모에 적어 둔다).

## 3. 단계

| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 1 펼치기 | `dsd-bridge export 전기.dsd -o 작업.xlsx` → `dsd-bridge describe 작업.xlsx`(표·열 역할·기간 표기 칸). 주석이 길면 `--split-notes`(주석 번호마다 시트) | 표 수·기간 표기 칸 수 보고 |
| 2 이월 | 재무제표 당기 열 → 전기 열, 당기 비움(세부↔세부, 합계↔합계, `-` 유지). 기간 표기는 `scripts/dsd_period.py`(미리보기 → `--apply`, 한 번에 치환해 연쇄 방지). 자본변동표: 옛 당기 구간 → 새 전기 구간, 새 당기 구간을 같은 구조로(구조가 바뀌면 `dsd_insert_rows.py`). 주석 표는 당기/전기 머리글 표만. 감사의견 문단 날짜 순서('당기말과 전기말') 확인 | `dsd-bridge diff --rollforward 전기펼친.xlsx 작업.xlsx` 기간 표기 미갱신 0 |
| 3 채우기 | 정산표 공시용(또는 BS/IS/CE/CF)·주석 시트에서 계정명으로 짝을 찾아 당기 기입. 주석은 천원 반올림(구성요소 반올림 합). 신규 계정은 표 안 같은 레벨 행 아래에 삽입. 0/0 행은 지우지 않고 목록 보고 | `dsd-bridge check 작업.xlsx --settlement 정산표.xlsx [--settlement-map map.json] --report 대사.xlsx` 금액 불일치 0 |
| 4 검증 | `dsd-bridge check 작업.xlsx`(세로 합계·총계·대차·자본변동표), 오타 의심 수정 후 재실행 | 불일치 0, 남은 것은 오탐 설명 |
| 5 되돌리기 | `dsd-bridge import 작업.xlsx --dsd 전기.dsd -o 당기_import.dsd`. 서식 조각(SPAN)이 섞인 칸을 고쳤다고 거부되면, 표시 차이가 없는 칸인지 확인 후 `--allow-lossy-mixed` | 바뀐 칸·삽입 수 보고, XSD 통과 |
| 6 XML 후처리 | `dsd_xml.py info` 로 점검 → `period`(기간 속성) → `acode`(신규 행) → `replace`(회색 문단) → `commas` → 마지막 파일을 `…_제N기 감사보고서_v1.dsd` 로 | info 다시 실행: 기간 속성 당기, 콤마 누락 0, 복제 코드 의심 0, XSD 통과 |
| 7 왕복 확인 | 결과 .dsd 를 다시 펼쳐 작업 엑셀과 비교, `dsd-bridge check 결과.dsd --xref`(계정코드가 있는 양식) | 차이 0 |
| 8 사람 | DART 편집기: 재무제표마다 표 안에 커서 → **F9** → **파일형식 검사** → 요약값 재추출 → `○` 채우기 → 등록·전송파일 생성. 편집기에서 저장하면 검사 상태가 지워지므로 저장 뒤 다시 검사 | 사용자에게 순서대로 안내 |

settlement-map 예(정산표 시트 이름이 표준과 다를 때, 숫자 이름 주석 시트 등):
```json
{"BS": ["공시용"], "IS": ["공시용"], "CE": ["공시용"], "CF": ["공시용"], "FN": ["주석"]}
```

## 4. DSD브릿지가 못 하는 것과 해결
- **기간 속성값(AUNITVALUE)**: 표지·첨부재무제표·외부감사 실시내용 칸의 PERIODFROM/TO, PERIODFROM2/TO2, SUB_PERIODFROM/TO 는 엑셀로 안 바뀐다 → `dsd_xml.py period 입력 -o 출력 YYYYMMDD YYYYMMDD`. 전기 파일에 몇 년 전 값이 남아 있던 사례가 있다
- **신규 행 계정코드(ACODE)**: 복제 삽입한 행은 위 행의 코드를 물려받는다 → 표준계정코드 표 `C:\DART\Resource\Code\A\PBS2.cod`(재무상태표)·`PIS2.cod`(손익)·`PCFI.cod`(간접법 현금흐름, cp949)에서 찾아 `dsd_xml.py acode 입력 -o 출력 "행 라벨" 코드`. 표에 없는 신설 계정은 `99999999999999`. 계정코드가 없는 양식(사모투자회사 등)은 해당 없음
- **회색 문단(서식 섞인 읽기 전용 문단)**: 엑셀에서 편집 불가 → 내용이 바뀔 때만 `dsd_xml.py replace` 로 글자 치환(예: 보고기간 후 사건이 당기 중 사건이 되면 삭제, 재무제표 확정일 번호·날짜)
- **콤마**: DSD브릿지는 기존 칸 표기를 따르므로 전기 값이 짧아 콤마가 없던 칸에 큰 수가 콤마 없이 들어간다 → `dsd_xml.py commas`(표 칸만, 요약값·날짜 제외)
- **칸 병합**: 새 표 행의 세로 병합(예: 특수관계자 표 회사명 2행)은 XML 에서 ROWSPAN 수정
- **COMM_DATE**: 지배기구 커뮤니케이션 일자 칸의 숨은 날짜 속성. 사용자가 일자를 주면 편집기에서 다시 입력하거나 XML 속성 갱신

## 5. 대사 '불일치'가 오탐인 경우 (칸을 직접 확인하고 설명)
- 같은 이름의 행이 두 번 나오면 다른 행과 짝지음, 복제 삽입 행이 원본과 같은 ID 로 짝지어짐
- 주석 현금 표 '금융기관' 열을 당기 세부 열로 오인, 차입금 표 세로 병합, 병합 표 열 판정 한계
- 현금흐름표 '부호주의'(유출 세부를 양수로 적는 기존 표기 관행)는 정상

## 6. 이월 때 자주 넘어오는 전기 오류 (매번 점검)
- 외부감사 실시내용 '감사대상 사업연도'가 옛 연도, 표 머리글 기수 갱신 누락, 재무상태표 머리글 연도 오기
- 로마 숫자 오기('Vl.' = V + 소문자 l → 'Ⅵ.', 'V.' → 'Ⅴ.'), 한 글자 오타(예: 외상매줄금 → 외상매출금), 과목명의 단위 표기 오기(예: 값은 1주당인데 과목명 단위가 다르게 적힌 경우)
- 정산표에는 있는데 dsd 에 없는 주석(또는 반대) → 주석 번호는 dsd 를 기준으로 하고 정산표 쪽을 맞출지 사용자에게 묻는다

## 7. 사전재무제표(감사전 재무제표, 문서코드 00860)
- DART 편집기 '감사보고서 변환' 결과물이다. 변환 규칙(감사보고서 ↔ 사전재무제표 실제 쌍으로 검증): ① ENG(영문) 속성 삭제 ② ACODE 값 비움 ③ 표 그룹명 `PBS-2:A`·`PIS-2:A`·`PCF-I:A` 의 `:A` 제거
- 만드는 법: `scripts/dsd_prefs.py 전기_사전재무제표.dsd 당기_감사보고서.dsd -o 당기_사전재무제표.dsd`. 전기 사전재무제표를 틀로 머리말·'감사보고서 변환' 표·제목·부속명세서 삽입부·meta.xml 은 유지하고, 표지~주석 끝을 당기 감사보고서 내용(규칙 적용)으로 바꾼다. 이어서 펼쳐서 `diff --rollforward`(기간 표기 미갱신 0)·`check` 확인
- 전기 사전재무제표와 감사보고서의 전기 값이 다르면 감사보고서(최종)를 따른다(감사에서 고쳐진 값)
- 감사보고서가 바뀌면 사전재무제표도 같은 규칙으로 다시 만든다

## 8. 검토보고서 .dsd (분기·반기 검토)
- 같은 원리(직전 보고서 → 당기). 반기 ↔ 분기로 바뀌면 문서코드·보고서 ID·표 그룹·강조문·파일명·제목·라벨을 바꿔야 한다 → `references/review-report-conversion.md` 전환표. 전년 같은 분기 최종 dsd 와 서식 골격 태그가 같은지 비교한다

## 9. 편집 절대 규칙 (작업 엑셀)
- A~E 숨김 열, `_dsdx`·`_dsdx_attrs` 시트(형식 표식, 이름은 옛 것 그대로) 손대지 않음. 행 정렬·재배열·열 삽입·표 신규 생성 금지(되돌리기가 거부)
- 새 행은 표 안 기존 행 아래, 삭제는 행 삭제. 회색 칸은 엑셀에서 고치지 않는다
- 숫자는 숫자로(괄호 음수는 음수), 16자리 이상 정수는 엑셀에 직접 치지 않는다(15자리로 잘림). 확신 없는 주석 본문은 고치지 말고 '확인 필요'
- 병합 칸이 있는 표의 행 삽입은 `dsd_insert_rows.py`(엑셀 조종). 빈 행은 되돌리기에서 무시되므로 끼운 뒤 내용을 채운다
- 작업 엑셀 형식 버전이 다르다고 거부되면 같은 버전으로 다시 펼친다(프로그램 업데이트 뒤 생길 수 있음)
