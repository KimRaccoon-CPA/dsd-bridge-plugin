# DSD브릿지: 전기 .dsd + 당기 정산표 → 당기 .dsd

DART 제출용 감사보고서 `.dsd`(ZIP 안 contents.xml·meta.xml)를 다음 기수로 넘긴다. 프로그램 DSD브릿지(`dsd_bridge.py`)가 펼치기·되돌리기·검증을 맡고, **판단이 필요한 편집(이월, 정산표 숫자를 계정에 맞춰 채우기)은 Claude 가 한다.** 사용자는 회계사다. 답은 한국어로, 회계·감사 용어는 풀어 쓰지 않는다. 산출물(dsd·엑셀·메모)에 긴 줄표 '—' 를 쓰지 않는다.

```
검토 끝난 당기 정산표 + 전기 감사보고서 .dsd → [DSD브릿지] → 당기 감사보고서 .dsd → (사전재무제표 .dsd) → 사용자: DART 편집기 검사·등록
```
보고서 숫자는 **검토 완료 정산표** 기준이다. 전기 열도 전기 공시값이 아니라 검토 완료 정산표의 전기 값(재분류·정정 반영)이다. 정산표가 아직 검토 전이면(당기 열이 옛 원천을 보거나 검증셀이 FALSE) 사용자에게 먼저 알린다.

## 0. 설치와 위치 (처음 쓰는 PC)

- **프로그램 폴더** = 이 플러그인의 루트 = 이 스킬 폴더(이 파일이 있는 곳)의 **두 단계 위**. 그 안에 `dsd_bridge.py`·`dsd-bridge.cmd`·`setup.ps1`·`requirements.txt` 가 있다. 아래에서 `<루트>` 로 쓴다.
- **전용 파이썬**(venv): Windows `%LOCALAPPDATA%\dsd-bridge\.venv\Scripts\python.exe`, 맥 `~/.venvs/dsd-bridge/bin/python`. 플러그인 폴더 밖에 두므로 플러그인을 업데이트해도 다시 만들 필요가 없다.
  - 없으면 만든다: Windows `powershell -ExecutionPolicy Bypass -File "<루트>\setup.ps1"`, 맥 `bash "<루트>/setup.sh"`.
  - 실행 정책으로 막히면 손으로: `py -3.13 -m venv "%LOCALAPPDATA%\dsd-bridge\.venv"` → 그 파이썬으로 `-m pip install -r "<루트>\requirements.txt"`.
  - 파이썬 3.13 이상이 없으면 사용자에게 설치를 안내한다(https://www.python.org/downloads/ 또는 `winget install Python.Python.3.13`).
  - 확인: `<파이썬> "<루트>/dsd_bridge.py" --version` 이 `dsd-bridge 0.x.y` 를 출력.
- 아래 명령의 `dsd-bridge` = `<파이썬> "<루트>/dsd_bridge.py"`. 출력 한글이 깨지면 `PYTHONIOENCODING=utf-8`(또는 `PYTHONUTF8=1`). `python -I` 는 쓰지 않는다.
- **DART 편집기**: Windows `C:\DART`. XSD(파일 규칙)는 `C:\DART\Resource\Dtd\Dart4.xsd` 를 자동으로 찾는다. 다른 곳이면 환경변수 `DSD_BRIDGE_DART_XSD_DIR`. 표준계정코드 표는 `C:\DART\Resource\Code\A\`.
- 이 스킬의 `scripts/`: `dsd_period.py`(기간 표기 일괄 갱신), `dsd_insert_rows.py`(병합 표 안 행 삽입, Windows 엑셀과 pywin32 필요: `No module named 'win32com'` 이면 `<파이썬> -m pip install pywin32` 한 번), `dsd_xml.py`(되돌린 뒤 점검 `info`·XSD, 남은 XML 손보기), `dsd_prefs.py`(사전재무제표 만들기). 같은 `<파이썬>` 으로 실행한다.
- 경로에 작은따옴표(`'26.09월`) 같은 특수문자가 있으면 스크립트에 경로를 인자로 넘긴다.
- **고객 파일은 고객 폴더에서만** 다루고 플러그인 폴더에 넣지 않는다. 작업 중간 파일은 임시 폴더(`$CLAUDE_JOB_DIR/tmp` 가 있으면 그곳), 결과물은 고객 기수 폴더에 **새 이름으로**(원본 덮어쓰기 금지).

## 1. 고객 메모 (사용자마다 따로)

반복 고객은 고객 메모를 쌓아 두면 다음 기수가 빨라진다. 메모는 **이 PC 사용자 것**이고 플러그인 폴더에 두지 않는다(업데이트 때 지워짐).

- 위치: `~/.dsd-bridge/config.json` 의 `clients_dir`(있으면), 없으면 `~/.dsd-bridge/clients/`(Windows `%USERPROFILE%\.dsd-bridge\clients\`). 파일 이름은 `<고객 이름>.md`.
- **시작할 때**: 그 고객 메모가 있으면 먼저 읽고 따른다(정산표 시트 대응, 보고서 규칙, 지난번 고친 점). 이름이 조금 달라도(약칭 등) 비슷한 파일을 찾아본다.
- **끝날 때**: 이번에 알게 된 것(정산표 시트·열 대응, settlement-map, 이월 때 고친 전기 오류, 사용자 결정, 작업 이력 한 줄)을 메모에 남길지 한 줄로 묻고, 사용자가 원하면 `templates/client-memo.md` 틀로 만들거나 고친다. config 에 `"memo": "auto"` 가 있으면 묻지 않고 바로 쓴다.
- 메모에는 금액 상세·개인정보를 적지 않고, 판단 규칙과 위치만 적는다.

## 2. 시작 전 확인

**전기 .dsd 가 없으면** 11절(다른 회사 .dsd 를 틀로)을 먼저 읽는다. 아래는 전기 .dsd 가 있을 때다.

전기 .dsd(날인본과 같은지), 검토 완료 당기 정산표, 기간 정보(제N기, 당기·전기 시작/종료일), 고객 메모의 보고서 규칙. 정산표에 없는 감사 정보(감사보고서일, 외부감사 실시내용 인원·시간·일정, 지배기구 커뮤니케이션 일자)는 `○` 로 두고 마지막에 요청한다. 임의감사처럼 외부감사 실시내용이 필요 없는 고객도 있다(고객 메모에 적어 둔다).

## 3. 단계

| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 1 펼치기 | `dsd-bridge export 전기.dsd -o 작업.xlsx` → `dsd-bridge describe 작업.xlsx`(표·열 역할·기간 표기 칸). 주석이 길면 `--split-notes`(주석 번호마다 시트) | 표 수·기간 표기 칸 수 보고 |
| 2 이월 | 재무제표 당기 열 → 전기 열, 당기 비움(세부↔세부, 합계↔합계, `-` 유지). 기간 표기는 `scripts/dsd_period.py`(미리보기 → `--apply`, 한 번에 치환해 연쇄 방지). 자본변동표: 옛 당기 구간 → 새 전기 구간, 새 당기 구간을 같은 구조로(구조가 바뀌면 `dsd_insert_rows.py`). 주석 표는 당기/전기 머리글 표만. 감사의견 문단 날짜 순서('당기말과 전기말') 확인 | `dsd-bridge diff --rollforward 전기펼친.xlsx 작업.xlsx` 기간 표기 미갱신 0. 3단계 뒤 한 번 더 돌려 `당기 미기입`, `전기와 같은 표`, `숫자가 든 문단이 전기와 같음` 목록을 하나씩 확인(5절) |
| 3 채우기 | 정산표 공시용(또는 BS/IS/CE/CF)·주석 시트에서 계정명으로 짝을 찾아 당기 기입. 주석은 천원 반올림(구성요소 반올림 합). 신규 계정은 표 안 같은 레벨 행 아래에 삽입. 0/0 행은 지우지 않고 목록 보고 | `dsd-bridge check 작업.xlsx --settlement 정산표.xlsx [--settlement-map map.json] --report 대사.xlsx` 금액 불일치 0, `주의:` 붙은 행과 `정산표에만 있음` 목록을 모두 확인해 처리(5절), 정산표 오류값·FALSE 안내가 있으면 사용자에게 먼저 알림 |
| 4 검증 | `dsd-bridge check 작업.xlsx`(세로 합계·총계·대차·자본변동표), 오타 의심 수정 후 재실행 | 불일치 0, 남은 것은 오탐 설명. 끝의 `확인 필요`(주석 참조 번호, 주석 번호 순서, 중복 행, 과목 없는 금액 행, 자리표시)를 고치거나 사유를 적음 |
| 5 되돌리기 | `dsd-bridge import 작업.xlsx --dsd 전기.dsd -o 당기_import.dsd [--acode "새 계정 라벨=표준계정코드" …]`. 새로 끼운 행마다 `--acode`(4절). 회색 칸은 서식을 두고 글자만 반영되고, 날짜 칸 글을 고쳤으면 숨은 날짜 속성값도 맞춰진다(출력의 `안내:` 줄). 그래도 회색 칸 편집이 거부되면(문단째 지우는 편집 등) 4절 | 바뀐 칸·삽입 수, `경고:` 줄(물려받은 계정코드, 날짜 속성 불일치) 0, XSD 통과 |
| 6 점검 | `dsd_xml.py info 당기_import.dsd`: 기간 속성이 당기, 콤마 누락 0, 복제 코드 의심 0. 남은 것만 4절 방법으로 고친 뒤 `…_제N기 감사보고서_v1.dsd` 로 | info 결과 이상 없음, XSD 통과 |
| 7 왕복 확인 | 결과 .dsd 를 다시 펼쳐 작업 엑셀과 비교, `dsd-bridge check 결과.dsd --xref`(계정코드가 있는 양식) | 차이 0 |
| 8 사람 | DART 편집기: 재무제표마다 표 안에 커서 → **F9** → **파일형식 검사** → 요약값 재추출 → `○` 채우기 → 등록·전송파일 생성. 편집기에서 저장하면 검사 상태가 지워지므로 저장 뒤 다시 검사 | 사용자에게 순서대로 안내 |

settlement-map 예(정산표 시트 이름이 표준과 다를 때. 주석 시트가 `1`~`19` 처럼 번호 이름이거나 이름에 `주석` 이 들었으면 0.3.0 부터 자동으로 주석으로 본다):
```json
{"BS": ["공시용"], "IS": ["공시용"], "CE": ["공시용"], "CF": ["공시용"], "FN": ["주석"]}
```

## 4. 되돌리기에서 자동으로 되는 것과 남는 것 (0.3.0)
- **기간 속성값(AUNITVALUE)**: 표지·첨부재무제표·외부감사 실시내용의 날짜 칸(PERIODFROM/TO, PERIODFROM2/TO2, SUB_PERIODFROM/TO, COMM_DATE)은 **칸 글을 고치면 숨은 속성값도 자동으로 맞춰진다**(`dsd_period.py` 로 기간 표기를 바꾸면 된다). 글에서 날짜 하나를 못 읽으면(`○`, `XXXX년`) 그대로 두고 `경고:`. 고치지 않은 칸인데 글과 속성이 다르면(전기 파일에 몇 년 전 값이 남은 사례) `경고:` 만 나오므로, 그 칸 날짜 글을 엑셀에서 한 번 고치거나 `dsd_xml.py period 입력 -o 출력 YYYYMMDD YYYYMMDD`
- **신규 행 계정코드(ACODE)**: 복제 삽입한 행은 위 행의 코드를 물려받는다(라벨이 다르면 `경고: … 물려받았습니다`). 표준계정코드 표 `C:\DART\Resource\Code\A\PBS2.cod`(재무상태표)·`PIS2.cod`(손익)·`PCFI.cod`(간접법 현금흐름, cp949)에서 찾아 **import 때 `--acode "행 라벨=코드"`**(여러 번 가능, 라벨은 엑셀에 보이는 그대로, 공백 무시). 표에 없는 신설 계정은 `99999999999999`. 계정코드가 없는 양식(사모투자회사 등)은 해당 없음. 이미 만든 .dsd 를 고칠 때는 `dsd_xml.py acode`
- **회색 칸·문단(서식 조각 SPAN 이 섞인 칸)**: 엑셀에서 **글자만 고치면 서식은 그대로** 반영된다(SPAN 안·밖 모두, 글자가 다 지워진 SPAN 은 요소째 삭제). 거부되는 경우(칸 안 문단 P 를 통째로 지우게 되는 편집 등)는 범위를 줄여 다시 하거나, 서식을 버려도 되면 `--allow-lossy-mixed`, 아니면 되돌린 뒤 `dsd_xml.py replace`
- **콤마**: 전기 값이 3자리 이하라 콤마가 없던 칸에 1,000 이상을 넣으면 같은 열(없으면 표)의 4자리 이상 숫자 표기를 따라 콤마를 넣는다. 그래도 `info` 에 콤마 누락이 보이면 `dsd_xml.py commas`
- **칸 병합**: 새 표 행의 세로 병합(예: 특수관계자 표 회사명 2행)은 XML 에서 ROWSPAN 수정
- **COMM_DATE 일자**: 지배기구 커뮤니케이션 일자 칸에 'YYYY년 MM월 DD일' 로 적으면 숨은 날짜도 맞춰진다. 커뮤니케이션 행을 새로 끼워도 새 행 날짜가 맞춰진다(못 읽으면 비움). 일자를 모르면 `○` 로 두고 마지막에 요청. 이 표의 `COMM_NO` 같은 코드는 계정코드가 아니므로 `--acode` 대상이 아니다

## 5. 주의·확인 필요 목록 읽는 법 (0.4.0, 판정이 '일치'여도 사람이 볼 것)
프로그램은 금액이 맞는지만 판정한다. 아래는 판정으로는 못 잡는 오류의 단서라서, **하나도 건너뛰지 말고** 칸을 확인해 고치거나 작업 메모에 사유를 남긴다(종료 코드는 안 바뀐다).
- `정산표에만 있음`(역방향 대사): 정산표에는 금액이 있는데 보고서 어느 행과도 짝지어지지 않은 행. 대사 범위 안의 것은 **보고서에 행이 빠진 신규 계정**일 수 있다 → 행을 끼우거나, 소계·작업용 행이면 사유 기록. 범위 밖은 `-v` 나 `--report` 엑셀의 `정산표에만 있음` 시트에서 훑어본다
- `주의: … 같은 금액의 정산표 행이 N개 더`: 계정과목이 달라 금액으로 짝지었는데 후보가 여럿 → 어느 계정인지 정산표에서 확인
- `주의: 정산표 …행을 이 표의 보고서 행 N개가 함께 씁니다`: 보고서에 같은 줄이 두 번 들어갔을 수 있음
- `주의: 당기·전기 금액이 정산표와 반대 열`: 당기와 전기를 바꿔 적었을 수 있음
- `주의: 부호만 다른 금액` / `1~2 차이(단수차)`: 불일치의 원인 단서
- `안내: 정산표 … 오류값` / `FALSE 인 칸` / `계산값이 저장돼 있지 않습니다`: 검토 전 정산표일 수 있으니 사용자에게 알리고 진행 여부를 묻는다
- `diff --rollforward` 의 `전기와 같은 표`(금액이 든 표가 전기 그대로)·`숫자가 든 문단이 전기와 같음`(금액·비율·날짜가 든 서술 문단이 글자 그대로): 주석 갱신 누락 후보. 정산표 주석 시트나 PBC 로 당기 값을 확인해 고치고, 바뀔 일이 없는 문단(기준서 적용일 등)은 그대로 둔다
- `check` 의 `확인 필요`: 주석을 지우거나 끼웠으면 뒤 주석 번호와 재무제표의 `(주석N)` 참조를 함께 고친다
- 대사 엑셀 `정보` 시트의 정산표 수정 시각·sha256: 납품 직전에 정산표가 그 뒤로 바뀌지 않았는지 확인하고, 바뀌었으면 대사를 다시 돌린다
- 되돌리기 `경고: 15자리가 넘는 숫자` / `원래 숫자였던 칸에 글자`: 엑셀에서 그 칸을 다시 확인

### 대사 '불일치'가 오탐인 경우 (칸을 직접 확인하고 설명)
- 같은 이름의 행이 두 번 나오면 다른 행과 짝지음, 복제 삽입 행이 원본과 같은 ID 로 짝지어짐
- 주석 현금 표 '금융기관' 열을 당기 세부 열로 오인, 차입금 표 세로 병합, 병합 표 열 판정 한계
- 현금흐름표 '부호주의'(유출 세부를 양수로 적는 기존 표기 관행)는 정상

## 6. 이월 때 자주 넘어오는 전기 오류 (매번 점검)
- 외부감사 실시내용 '감사대상 사업연도'가 옛 연도, 표 머리글 기수 갱신 누락, 재무상태표 머리글 연도 오기

## 7. 사전재무제표(감사전 재무제표, 문서코드 00860)
- DART 편집기 '감사보고서 변환' 결과물이다. 변환 규칙(감사보고서 ↔ 사전재무제표 실제 쌍으로 검증): ① ENG(영문) 속성 삭제 ② ACODE 값 비움 ③ 표 그룹명 `PBS-2:A`·`PIS-2:A`·`PCF-I:A` 의 `:A` 제거
- 만드는 법: `scripts/dsd_prefs.py 전기_사전재무제표.dsd 당기_감사보고서.dsd -o 당기_사전재무제표.dsd`. 전기 사전재무제표를 틀로 머리말·'감사보고서 변환' 표·제목·부속명세서 삽입부·meta.xml 은 유지하고, 표지~주석 끝을 당기 감사보고서 내용(규칙 적용)으로 바꾼다. 이어서 펼쳐서 `diff --rollforward`(기간 표기 미갱신 0)·`check` 확인
- 전기 사전재무제표와 감사보고서의 전기 값이 다르면 감사보고서(최종)를 따른다(감사에서 고쳐진 값)
- 감사보고서가 바뀌면 사전재무제표도 같은 규칙으로 다시 만든다

## 8. 검토보고서 .dsd (분기·반기 검토)
- 같은 원리(직전 보고서 → 당기). 반기 ↔ 분기로 바뀌면 문서코드·보고서 ID·표 그룹·강조문·파일명·제목·라벨을 바꿔야 한다 → `references/review-report-conversion.md` 전환표. 전년 같은 분기 최종 dsd 와 서식 골격 태그가 같은지 비교한다

## 9. 편집 절대 규칙 (작업 엑셀)

- 새 행은 표 안 기존 행 아래, 삭제는 행 삭제. 회색 칸(서식 조각이 섞인 칸)은 글자만 고친다(서식은 되돌릴 때 유지). 새 행은 되돌릴 때 `--acode` 로 계정코드를 준다

- 병합 칸이 있는 표의 행 삽입은 `dsd_insert_rows.py`(엑셀 조종). 빈 행은 되돌리기에서 무시되므로 끼운 뒤 내용을 채운다
- 작업 엑셀 형식 버전이 다르다고 거부되면 같은 버전으로 다시 펼친다(프로그램 업데이트 뒤 생길 수 있음)

## 11. 전기 .dsd 가 없을 때: 다른 회사 .dsd 를 틀로 (0.5.0)
DSD브릿지는 표·섹션을 새로 만들지 못하므로 틀이 될 .dsd 가 있어야 한다. 먼저 회사·전기 감사인에게 전기 .dsd 를 요청하고, 없으면 ① DART 편집기에서 감사보고서 서식으로 새 문서를 만들어 저장한 파일(틀 잔존 위험이 없다) 또는 ② 비슷한 다른 회사의 .dsd 를 틀로 쓴다. ②의 가장 큰 위험은 **틀 회사의 것이 결과에 남는 것**(비밀유지 위반, 다른 회사 고유번호로 제출)이다.

**틀 고르기**: 같은 보고서 종류·같은 회계기준(K-IFRS/일반기업회계기준, 별도/연결)·같은 구조(펀드·리츠·SPC·일반법인)·같은 감사인 문안, 최신 서식(`template 틀.dsd` 의 서식이 dart4), **주석과 계정이 더 많은 쪽**(행·문단 지우기는 되지만 표·섹션은 새로 못 만든다).

**비밀유지**: 틀 회사 원본은 새 고객 폴더에 두지 않는다. 작업은 임시 폴더에서 하고(작업 엑셀에 틀 회사 숫자가 들어 있다) 끝나면 중간 파일을 지운다. 고객 메모·작업 메모에 틀 회사 이름을 적지 않는다.

| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0 식별값 | `dsd-bridge template 틀.dsd` 로 틀의 회사 이름·숨은 고유번호·법인등록번호·요약값·날짜·표지 머리말 확인. 사용자에게 새 회사 정보 요청(회사 이름 정식 표기, 대표이사, 주소, 설립일, 기수·사업연도, 감사보고서일, 감사 실시내용) | 새 회사 정보 확보, 없는 것은 `○` |
| 1 틀 정리 | `dsd-bridge template 틀.dsd --scrub -o <임시>/새틀.dsd --replace "옛 회사 이름=새 회사 이름"`(대표이사·주소도 `--replace` 추가). 표지 머리말은 엑셀에 나타나지 않아 **여기서만** 바뀐다 | 비운 숨은 값 목록, XSD 통과 |
| 2 펼치기 | `export 새틀.dsd` → `describe` | 표·기간 표기 칸 파악 |
| 3 기간 | `scripts/dsd_period.py` 로 틀의 기수·기간을 새 회사 것으로(사업연도 길이가 다르면 표기 전부 확인) | 틀 날짜 표기 0 |
| 4 내용 교체 | 재무제표 표의 **당기·전기 금액 칸을 먼저 모두 비운 뒤** 정산표로 채운다(틀 금액 잔존 방지). 틀에만 있는 계정 행은 삭제, 정산표에만 있는 계정은 끼움. 주석은 회사 개요·회계정책·우발부채·특수관계자·보고기간 후 사건을 포함해 **전부 새 회사 내용으로 다시 쓰거나 지운다**. 필요한 표가 틀에 없으면 만들 수 없으니 사용자에게 알린다(DART 편집기에서 표 추가 후 다시 펼치기) | `check --settlement`: 금액 불일치 0, `라벨 미발견`(틀에만 있던 계정) 0, `정산표에만 있음` 처리 |
| 5 잔존 검사 | `dsd-bridge template 틀.dsd --check 작업.xlsx` (전기 문서가 아니므로 `diff --rollforward` 는 쓰지 않는다) | 식별값 잔존 0, 틀 금액 잔존·틀 글 확인 |
| 6 되돌리기 | `import 작업.xlsx --dsd 새틀.dsd -o 결과.dsd`(많이 지웠으면 `--allow-bulk-delete`, 새 행은 `--acode`) → `dsd-bridge template 틀.dsd --check 결과.dsd --old "틀 회사 대표이사" --old "틀 회사 주소 일부" -v` | **식별값 잔존 0(종료 코드 0), 숨은 값이 틀과 같음 0, 금액·날짜가 든 틀 글 0**. 틀 금액 잔존은 하나씩 확인해 우연히 같은 금액만 남기고 작업 메모에 적는다. `-v` 의 '그 밖 틀과 같은 글'을 훑어 회사 고유 내용이 없는지 본다 |
| 7 사람 | DART 편집기: 회사 지정(제출인 정보)·F9·파일형식 검사·요약값 재추출. 숨은 회사 고유번호를 비웠으므로 회사 지정이 필요한지 편집기에서 확인 | 사용자에게 안내 |

**이때 생기는 문제와 대응**
- 틀 회사 이름이 띄어 쓴 형태(`옛 날 상 사`)나 약칭으로 남음 → `--check` 가 공백을 없애고 찾는다. 약칭·영문명·대표이사·주소는 `--old` 로 더 찾는다
- 엑셀에 안 보이는 곳(표지 머리말, COMPANY-NAME, EXTRACTION, meta.xml)에 남음 → `--scrub`, 결과 .dsd 로 `--check`(작업 엑셀 검사만으로 끝내지 않는다)
- 틀 금액이 남음(특히 주석 표, 외부감사 실시내용의 인원·시간) → `--check` 의 틀 금액 잔존. 자본금처럼 우연히 같은 금액은 메모
- 틀 주석 문장이 남음 → 금액·날짜가 든 것은 목록, 표준 문안은 건수만. 감사의견 문단의 틀 회사 고유 문단(강조사항·핵심감사사항·계속기업·기타사항)은 사용자에게 유지 여부를 묻는다
- 계정 구성이 달라 대사 결과가 지저분함 → `라벨 미발견` = 틀에만 있던 계정(삭제), `정산표에만 있음` = 새 회사 계정(끼움)으로 읽는다
- 틀의 계정코드: 틀 회사 신설 계정(99999999999999, PC 별 비표준 계정)이 남으면 F9 오류 → 새 행·바꾼 행은 `--acode`, 마지막에 `dsd_xml.py info`
- 주석 번호가 바뀜 → `check` 의 확인 필요(주석 번호·참조)
- 숨은 날짜 값 → 날짜 칸 글을 고치면 같이 바뀐다. `--check` 의 '숨은 날짜 값이 틀과 같음' 0 확인
- 전기 비교 금액 → 정산표의 전기 열로 채운다. 최초 외부감사라 전기가 감사받지 않았으면 표시 방법(전기 열 표기, 기타사항 문단)은 사용자가 정한다
- 서식 버전이 옛것(dart3) → 편집기에서 변환·정정 안내가 날 수 있으니 최신 서식 틀을 쓴다
